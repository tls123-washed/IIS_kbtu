# Проверки Campus Threads

Для задания «test/front 20 test» подготовлены 20 браузерных сценариев в `tests/front/run.mjs`. Формулировка задания пока принята как 20 функциональных проверок интерфейса. Проверки выполняются через настоящий Chromium и HTTP API на отдельной PostgreSQL с именем `*_test`.

```powershell
npm install
npx playwright install chromium
npm run test:front
```

Отдельно выполняются 5 проверок запуска при недоступных запросах и файлах:

```powershell
npm run test:startup
```

Проверяются быстрый вход для гостя без запросов сессии, повтор после ошибки БД, тайм-аут проверки входа, ошибка и зависание загрузки основного JavaScript. Результаты сохраняются в `tests/reports/startup.json`. Этот прогон также использует отдельную базу `*_test` и выполняется последовательно с остальными.

Нужны установленный Python с зависимостями `requirements-dev.txt` и доступная тестовая PostgreSQL. Можно задать `TEST_DATABASE_URL`. При запуске в подготовленном локальном окружении используется `campus_threads_test`. Перед прогоном тестовые пользовательские таблицы очищаются, потом создаются тестовые профили, треды, клуб и мероприятие.

Нагрузку запускает `tests/load.py`. Каждый виртуальный пользователь выполняет запросы ленты, поиска, лайков и ответов с паузой 100 мс между действиями. По умолчанию проверяются группы 20, 50 и 100 пользователей, по 12 действий на каждого.

```powershell
.\.venv\Scripts\python.exe tests/load.py
```

В `tests/reports/front.json` и `tests/reports/load.json` сохраняются измерения. Скриншоты десктопа сохраняются рядом. Прогоны используют общую тестовую базу и выполняются последовательно.

Для API:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
```

Результаты нагрузки относятся к машине, на которой выполнен прогон. Для оценки Render/Neon нужно провести измерение на размещённом тестовом экземпляре с такой же конфигурацией и отдельной тестовой базой.

SQL-снимок для восстановления базы находится в [database/](../database/README.md). Его восстановление в пустую PostgreSQL проверено запуском того же набора API-тестов на восстановленной базе. Отчёты: `tests/reports/database-restore.json` и `tests/reports/api.json`.
