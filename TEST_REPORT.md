## API

Команда: `.venv\Scripts\python.exe -m unittest discover -s tests -p test_pilot.py -v` при заданном `TEST_DATABASE_URL`. Результат: `Ran 11 tests ... OK`. В том числе проверяются регистрация и сессии, права на публикации, модерация, билеты и гонка за последнее место. Запросы выполняются на отдельной базе с именем, оканчивающимся на `_test`.

Каждый виртуальный пользователь имеет свою сессию и выполняет 12 действий с паузой 100 мс между ними. Состав: 50% лента, остальные поровну лайки, поиск и ответы. Это одновременные HTTP-клиенты, а не 100 запущенных браузеров. Регистрация и вычисление хеша пароля при входе в этот замер не входят.

Среда: Python 3.12.14, Windows, 12 логических процессоров AMD, PostgreSQL на той же машине, пул до 8 соединений. Перед началом создаются 35 корневых публикаций; ответы добавляются в ходе нагрузки. Длительность этапов: 1,65 / 3,53 / 8,40 секунды. Эти короткие проверки подтверждают работу указанных сценариев, но не моделируют большой накопленный объём данных, длительную работу и спящий бесплатный сервер.

### Найденный и исправленный сбой

До исправления при 50 пользователях 36 из 600 запросов получили ошибку 503; 95-й процентиль был 5 107 мс. Ожидающие соединение с PostgreSQL запросы занимали общие рабочие потоки FastAPI и мешали завершать запросы, уже получившие соединения.

В `server/db.py` ожидание соединений перенесено на отдельный ограничитель, а возврат соединения выполняется с защитой от отмены запроса. После изменения 50 и 100 пользователей прошли без ошибок. Первичные данные сохранены в `tests/reports/load-before.json`, повторный замер — в `tests/reports/load.json`.

## Как повторить

Инструкции и зависимости находятся в [tests/README.md](tests/README.md). Браузерный и нагрузочный прогоны выполняются последовательно: они очищают общую тестовую базу. Основная база приложения в этих прогонах не очищается.

Для защиты корректная формулировка: «20 браузерных сценариев и 11 проверок API прошли; в локальном коротком прогоне 100 одновременных клиентов выполнили 1 200 запросов без ошибок. Предел облачного сервера требует отдельного измерения».
