# Бесплатное размещение Campus Threads

Текущее размещение: **https://campus-threads-am1s.onrender.com/**. Подключение к Neon и основные действия двух пользователей проверены 18 ноября 2026 года. Результаты — в [TEST_REPORT.md](TEST_REPORT.md). Аккаунты из локальной базы автоматически не переносились.

Сервер FastAPI и файлы интерфейса размещаются на Render Free. База PostgreSQL размещается на Neon Free. Сайт будет доступен по HTTPS-адресу Render, пока твой ПК выключен. pgAdmin можно подключить к Neon для просмотра таблиц и выполнения SQL.

## 1. Создай базу

Войди в [Neon](https://console.neon.tech/) через GitHub. Создай проект Campus Threads на плане Free, выбери регион Frankfurt. В **Connect** скопируй строку подключения PostgreSQL с `sslmode=require`. Для миграций и этого приложения используй прямое подключение, выключив переключатель **Connection pooling**. Приложение само держит пул до восьми соединений.

## 2. Добавь код в GitHub

Загрузи проект в свой репозиторий. `.gitignore` исключает локальный `.env`, PostgreSQL, письма и рабочие файлы. В репозитории должны быть `server/`, `pilot/`, `site/`, `requirements.txt` и `render.yaml`. Выбери Private, если доступ к исходникам нужен только команде и преподавателю.

## 3. Создай сервер

Войди в [Render](https://dashboard.render.com/) через GitHub. Открой **New → Blueprint**, выбери репозиторий и согласись с конфигурацией из `render.yaml`. План сервера должен быть **Free**. В поле `DATABASE_URL` вставь строку Neon. Значение `APP_SECRET` Render сгенерирует сам.

Команда запуска `python -m server.cloud` применит SQL-миграции к новой базе и запустит приложение на порту, который выдаст хостинг. `APP_ORIGIN` автоматически определяется по `RENDER_EXTERNAL_URL`. Успешная проверка `/api/health` подтверждает соединение с базой.

## 4. Проверь сайт

Открой адрес `https://имя-сервиса.onrender.com`. Он сразу покажет вход и регистрацию Campus Threads. Сейчас регистрация принимает адреса `@kbtu.kz` и пароль. Окончание адреса проверяется, а владение ящиком пока не подтверждается.

Чтобы твой профиль `tls` мог публиковать события, после его регистрации выполни в **Neon → SQL Editor**:

```sql
SELECT campus_api.grant_event_organizer('tls');
```

Модерка сайта также даёт право создавать мероприятия: `SELECT campus_api.change_moderator('логин', TRUE);`. Дополнительно назначать организатора такому пользователю не нужно. Роль модератора отдельного сообщества действует только на его публикации. Кнопка «Создать мероприятие» находится в разделе «Мероприятия», включая вкладку «Мои билеты».

## 5. Подключи pgAdmin

В pgAdmin выбери **Register → Server**. В **Connection** укажи хост, базу, пользователя и пароль из окна **Connect** Neon. В настройках SSL выбери **Require**. После подключения увидишь схемы `public` и `campus_api`. Определения таблиц и функций создаются миграциями из репозитория.

## Ограничения бесплатных планов

Render Free засыпает после 15 минут без входящих запросов. Первое открытие после простоя может занять около минуты. Neon Free тоже приостанавливает вычисления при простое. Это нужно учитывать на защите и при измерении нагрузки. [Render Free](https://render.com/docs/free), [Neon Free](https://neon.com/docs/introduction/plans)

Локальные нагрузочные тесты и короткая облачная проверка описаны отдельно в [TEST_REPORT.md](TEST_REPORT.md). При 20 одновременных HTTP-клиентах облачный прогон чтения завершился без ошибок, но с длинными задержками части ответов. Это не измерение максимального числа пользователей и не гарантия скорости при постоянной нагрузке.
