# Campus Threads — пять выступлений на защите

Campus Threads — соцсеть КБТУ. Браузер открывает интерфейс HTML/CSS/JavaScript и обращается к FastAPI по HTTPS. Python вызывает функции и процедуры PostgreSQL. Интерфейс и API размещены на Render, база — на Neon.

## 1. Интерфейс, поиск и мероприятия

**Что сказать.** «Мы добавили английский интерфейс в настройки. Браузер запоминает выбранный язык. В одном поиске можно найти профили, публикации, сообщества и мероприятия. Точный запрос `#хэштег` выдаёт публикации с этим тегом. При создании мероприятия можно прикрепить фото. Когда событие начинается, его карточка появляется в архиве, где видно, сколько пропусков выдали и сколько посещений отметили. Организатор или модератор отмечает участника по номеру пропуска».

**Что показать.** Боковая панель → «Язык интерфейса» → English. В поиске введи существующий тег или название клуба. В «Мероприятиях» покажи «Архив» и карточку. Публикацию покажи с аккаунта организатора или модератора сайта. Фото можно выбрать в форме создания.

**Если спросят про историю.** Старые события остаются в базе. Граница архива — время начала, потому что в форме пока нет времени окончания. Исторические отметки появляются только после ручной регистрации прихода. Ноль в старой карточке означает, что отметок в системе нет.

## 2. Тесты и три бага

**Что сказать.** «Мы прогнали 20 браузерных сценариев через реальный интерфейс и API на отдельной PostgreSQL. Три проблемы сначала воспроизвели в предыдущей версии. Поиск по `#python` возвращал результаты с `#pythonics`, поэтому подключили точный поиск по таблице тегов. Последний администратор мог уйти из сообщества, поэтому PostgreSQL теперь отклоняет такой выход. Если афиша длинная, созданное событие могло оказаться за первой страницей. Теперь после публикации открывается его карточка по ID. Все 20 сценариев прошли, включая проверки этих трёх случаев».

**Что показать.** `tests/reports/front.json`, сценарии 16–18, а затем `tests/reports/bugs-before.json`. Дополнительно прошли 5 проверок запуска, 2 сценария мероприятий и 13 тестов API, включая работу с архивом, обложкой и повторной отметкой посещения.

**Если спросят про нагрузку.** Эти 20 сценариев проверяют работу функций. Количество одновременно работающих пользователей измеряется отдельным нагрузочным прогоном.

## 4. Датасет для анализа мероприятий

**Что сказать.** «У нас отдельный учебный CSV на 20 вымышленных мероприятий пяти категорий. Одна строка — одно мероприятие. В ней есть вместимость, выданные пропуска и условное число пришедших. В выборке 675 пропусков и 522 посещения, то есть примерно 77,3% по всем выданным пропускам. По этим данным можно сравнить интерес к категориям и явку по датам».

**Что показать.** Загрузи `campus_events_20.csv` в Colab через панель «Файлы» и выполни ячейку. Первые пять строк подтвердят, что файл прочитался, а график сравнит пропуска и посещения по категориям.

```python
import pandas as pd

events = pd.read_csv('/content/campus_events_20.csv', parse_dates=['starts_at'])
display(events.head())
counts = events.groupby('category')[['tickets_issued', 'checked_in_count']].sum()
counts.columns = ['Выдано пропусков', 'Условно пришли']
counts.plot.barh(title='Пропуска и условные посещения по категориям')
```

**Если спросят про проценты.** `fill_pct` — пропуска / вместимость × 100. `check_in_pct` — отметки / пропуска × 100. Датасет помечен `synthetic` и загружается отдельно в Colab.

## 5. Хранение действий и сводка команды

**Что сказать.** «Аккаунты, публикации, лайки, сообщества, мероприятия и билеты сохраняются в PostgreSQL на Neon. Сервер читает агрегаты из представления `campus_api.live_summary`. Модератор сайта открывает “Сводку команды”, и браузер запрашивает актуальные числа примерно каждые 10 секунд, пока вкладка открыта. Например, пользователь получает бесплатный пропуск, а в сводке автоматически растёт счётчик выданных пропусков».

**Что показать.** На первом устройстве или в первом профиле браузера открой «Сводку команды» под модератором. На втором получи пропуск на заранее созданное будущее мероприятие. Вернись в сводку и посмотри счётчик. Для проверки без переключения вкладок удобно держать первый экран открытым на ноутбуке, а второй — на телефоне.

**Если спросят про историю.** Сводка показывает текущее состояние. Если пользователь снимет лайк, число лайков уменьшится. Отдельного журнала каждого клика в этом модуле нет.
